# Socket.IO Event Contract

## Overview

This document defines the Socket.IO events exchanged between the SME
Booking System frontend and backend.

All connections must be authenticated through the `accessToken`
HTTP-only cookie before events can be sent or received.

## Conventions

- Event names use the `resource:action` format.
- MongoDB identifiers are serialized as strings.
- Dates are serialized as ISO 8601 strings.
- The authenticated `businessId` and `userId` are obtained from
  `socket.data.user`.
- Clients must not supply trusted tenant or user identity values.
- Unknown fields may be added in future versions and should be ignored.
- Existing fields must not change meaning without a versioned event.

## Rooms

| Room | Name | Membership |
|---|---|---|
| Business | `business:{businessId}` | Joined automatically after authentication |
| User | `user:{userId}` | Joined automatically after authentication |
| Conversation | `conversation:{conversationId}` | Joined after tenant authorization |

## Client command acknowledgements

Every client command accepts a Socket.IO acknowledgement callback.

### Success

```json
{
  "success": true,
  "data": {}
}
```

### Failure

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Safe client-facing message"
  }
}
```

Authentication details, raw tokens, stack traces, database errors, and
internal exception messages must never be returned.

# Client commands

## `conversation:join`

Requests membership in a conversation room.

The server verifies that the conversation belongs to the authenticated
user's business before joining the room.

### Payload

```json
{
  "conversationId": "507f191e810c19729de860ea"
}
```

### Success acknowledgement

```json
{
  "success": true,
  "data": {
    "conversationId": "507f191e810c19729de860ea"
  }
}
```

### Error codes

- `INVALID_PAYLOAD`
- `CONVERSATION_NOT_FOUND`
- `INTERNAL_ERROR`

The response does not reveal whether a conversation exists under
another tenant.

## `conversation:leave`

Removes the current socket from a conversation room.

### Payload

```json
{
  "conversationId": "507f191e810c19729de860ea"
}
```

### Success acknowledgement

```json
{
  "success": true,
  "data": {
    "conversationId": "507f191e810c19729de860ea"
  }
}
```

### Error codes

- `INVALID_PAYLOAD`
- `INTERNAL_ERROR`

## `message:send`

Creates an outbound message in an authorized conversation.

`businessId`, `senderUserId`, `senderType`, and `direction` are derived
by the server from the authenticated user.

### Payload

```json
{
  "conversationId": "507f191e810c19729de860ea",
  "body": "Your appointment has been confirmed.",
  "clientMessageId": "8bb71b79-2644-47fb-9839-e45c06d26e77"
}
```

`clientMessageId` is generated by the frontend and allows it to match an
optimistic message with the saved server message.

### Success acknowledgement

```json
{
  "success": true,
  "data": {
    "clientMessageId": "8bb71b79-2644-47fb-9839-e45c06d26e77",
    "messageId": "507f1f77bcf86cd799439011"
  }
}
```

### Error codes

- `INVALID_PAYLOAD`
- `CONVERSATION_NOT_FOUND`
- `MESSAGE_EMPTY`
- `MESSAGE_TOO_LONG`
- `INTERNAL_ERROR`

## `message:mark-read`

Marks inbound messages in an authorized conversation as read.

### Payload

```json
{
  "conversationId": "507f191e810c19729de860ea"
}
```

### Success acknowledgement

```json
{
  "success": true,
  "data": {
    "conversationId": "507f191e810c19729de860ea",
    "readAt": "2026-08-04T06:30:00.000Z"
  }
}
```

### Error codes

- `INVALID_PAYLOAD`
- `CONVERSATION_NOT_FOUND`
- `INTERNAL_ERROR`

# Server events

## `conversation:created`

Sent when a new conversation is created.

### Audience

```text
business:{businessId}
```

### Payload

```json
{
  "conversation": {
    "id": "507f191e810c19729de860ea",
    "clientId": "507f1f77bcf86cd799439012",
    "appointmentId": null,
    "channel": "web",
    "status": "open",
    "unreadCount": 1,
    "lastMessageAt": "2026-08-04T06:30:00.000Z",
    "lastMessagePreview": "Hello, I need help booking.",
    "lastMessageDirection": "inbound",
    "lastMessageSenderType": "client",
    "createdAt": "2026-08-04T06:30:00.000Z",
    "updatedAt": "2026-08-04T06:30:00.000Z"
  }
}
```

The payload must not expose another tenant's data.

## `conversation:updated`

Sent when conversation metadata changes.

### Audience

```text
business:{businessId}
conversation:{conversationId}
```

### Payload

```json
{
  "conversation": {
    "id": "507f191e810c19729de860ea",
    "status": "open",
    "unreadCount": 0,
    "lastMessageAt": "2026-08-04T06:30:00.000Z",
    "lastMessagePreview": "Your appointment has been confirmed.",
    "lastMessageDirection": "outbound",
    "lastMessageSenderType": "staff",
    "updatedAt": "2026-08-04T06:31:00.000Z"
  }
}
```

## `message:created`

Sent after a message has been persisted successfully.

### Audience

```text
business:{businessId}
conversation:{conversationId}
```

### Payload

```json
{
  "message": {
    "id": "507f1f77bcf86cd799439011",
    "conversationId": "507f191e810c19729de860ea",
    "direction": "outbound",
    "senderType": "staff",
    "senderUserId": "507f1f77bcf86cd799439012",
    "body": "Your appointment has been confirmed.",
    "deliveryStatus": "sent",
    "processingStatus": null,
    "receivedAt": null,
    "readAt": null,
    "createdAt": "2026-08-04T06:30:00.000Z",
    "updatedAt": "2026-08-04T06:30:00.000Z"
  }
}
```

`businessId` is intentionally omitted because room membership already
establishes the tenant context.

## `message:processing`

Sent when AI processing begins for an inbound message.

### Audience

```text
conversation:{conversationId}
```

### Payload

```json
{
  "conversationId": "507f191e810c19729de860ea",
  "messageId": "507f1f77bcf86cd799439011",
  "processingStatus": "pending"
}
```

## `message:intent-ready`

Sent when intent processing completes successfully.

### Audience

```text
conversation:{conversationId}
```

### Payload

```json
{
  "conversationId": "507f191e810c19729de860ea",
  "messageId": "507f1f77bcf86cd799439011",
  "processingStatus": "processed",
  "parsedIntent": {
    "intent": "create_appointment"
  }
}
```

The exact `parsedIntent` fields follow the backend parsed-intent schema.

## `message:processing-failed`

Sent when message processing fails.

### Audience

```text
conversation:{conversationId}
```

### Payload

```json
{
  "conversationId": "507f191e810c19729de860ea",
  "messageId": "507f1f77bcf86cd799439011",
  "processingStatus": "failed",
  "error": {
    "code": "PROCESSING_FAILED",
    "message": "Message processing failed"
  }
}
```

Internal AI, database, and stack-trace details must not be included.

## `message:read`

Sent after messages are marked as read.

### Audience

```text
business:{businessId}
conversation:{conversationId}
```

### Payload

```json
{
  "conversationId": "507f191e810c19729de860ea",
  "readAt": "2026-08-04T06:30:00.000Z",
  "readByUserId": "507f1f77bcf86cd799439012",
  "unreadCount": 0
}
```

# Compatibility rules

- New optional fields may be added without changing the event name.
- Existing fields must not be removed or given a different meaning.
- A breaking payload change requires a versioned event such as
  `message:created:v2`.
- Consumers must ignore unknown fields.
- Event payloads must contain JSON-serializable values only.
